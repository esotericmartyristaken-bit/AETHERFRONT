Current implementation
----------------------
1. ReadSnapshot captures the committed immutable JSON under the store gate,
   then deserializes outside it. It no longer serializes the entire state just
   to make another snapshot. Bootstrap still captures uncommitted initialization
   state correctly. Native copy-on-write commits and durable acknowledgement
   ordering were not replaced by asynchronous or best-effort writes.

2. Native snapshot requests enqueue a coalesced background encoder. Native
   visibility and personal-progression filtering are retained. Permission,
   account, suspension, revision and subspace checks run again before sending.
   Encoding and envelope serialization no longer occupy the gameplay dispatcher
   or fleet gate. One pending request per connection is retained while encoding.

3. Client polls advertise a revision and delta capability. The server retains
   two authorized projections per connection. Changed sections and changed craft
   records are sent with an exact base revision; deletions use a validated order
   list. Unchanged polls omit the state body but still refresh vessel interest.
   A missing/invalid base requests a full snapshot. A delta larger than a full
   snapshot falls back to a full snapshot. Actual visibility changes are compared
   even at an unchanged ledger revision, because permission leases can expire.
   Canonical JSON slices avoid thousands of per-craft serializer constructions.

4. Backup capture serializes a stable vessel under the fleet gate. Large staging
   writes and Flush(true) execute outside fleet/backup gates. Final atomic
   publication validates capture order, vessel identity and deletion tombstones
   under the original lock order. Native removal and restoration transactions
   remain authoritative. A flushed stale backup cannot resurrect a deleted
   vessel or overwrite a later capture. This remains a snapshot at capture time;
   it does not promise that a backup contains later unacknowledged live updates.

5. Timings distinguish queue wait, handler duration, fleet/store/backup lock
   waits and holds, state and vessel serialization, disk write and durable flush.
   Native commit operations remain synchronous. Metrics, not weakened durability,
   are the basis for deciding whether further commit-path changes are justified.

6. Warp requests and replies carry explicit 64-bit session and request IDs.
   Exact retries replay only a committed transition. The actual packet-intake
   boundary captures reply arrival time before Unity's queue, copies values and
   recycles the message exactly once. Matching queued replies are considered
   before timeout. Previous sessions, retired requests, changed retries, invalid
   clock corrections and replies arriving after the deadline remain rejected.

7. Synchronization waits until the scene/vessel is ready. Scene changes,
   termination and connection loss retire pending requests. Physics remains
   protected while leaving flight. A native-pause compatibility hook allows the
   guard's pause to work despite LMP's normal pause veto. Owned pause/time scale
   and throttle are tracked separately; cancellation never restarts an engine,
   and a replacement vessel never inherits throttle. An unscaled safe-disconnect
   button remains available. No blanket removal of other mods' input locks occurs.
   KSP event callbacks use non-null instance targets.

8. Identical outstanding fleet requests, unchanged vessel definitions and exact
   snapshot queries are deduplicated. Reliable mutations are barriers: A,B,A
   definitions preserve the final A. Queued discarded messages are recycled.
   Bulk application pacing increases from 512 KiB/s to 4 MiB/s, with a 1 MiB
   burst; the native memory/fragment windows remain unchanged. Control traffic
   can bypass a capacity-blocked bulk lane. Science/resource mutations are not
   discarded or coalesced as if they were cosmetic updates.

9. Personal-checkpoint loading keeps the existing server transaction and normal
   disconnect. A matching locally requested restore disconnect now schedules
   native exit to MAINMENU before automatic reconnect. Reconnect waits for native
   reset, uses the normal approved endpoint/identity/pack checks, and is limited
   to three attempts with cancellation and an expiry. No password is written to
   a file or log. Ordinary timeouts cannot trigger this checkpoint reconnect.
   Native connection calls execute outside the reconnect helper's gate to avoid
   inversion with the native session gate.

10. Warp control is admitted before local recovery capture, and normal boundary
    capture includes only the active owned vessel. One faulty vessel module no
    longer aborts capture of other healthy vessels: a partial file has explicit
    SKIPPED_VESSEL records and a different name. It cannot overwrite the last
    complete recovery. No life-support epoch or crew record is silently reset.
